Skill workflow

reflect-api-change-into-notion

Detects API-relevant changes in the member, comment, and search domains and in the auth surface, then writes and applies edits to the matching Notion API-spec pages.

Skill file: .claude/skills/reflect-api-change-into-notion/SKILL.md. That file is the source of truth; this page is a human-oriented view of it.

Step, in run order Document read File written External system Terminate or skip Branch or fallback Repeated per item
  1. 1

    Resolve Target Classes

    Collect every .java class not yet pushed: uncommitted changes (git status --porcelain) combined with committed-but-unpushed ones (git diff against the upstream, or origin/main if none).

    The combined list is empty.
  2. 2

    Filter to the watched API surface

    Keep only classes listed in the skill's Codebase → Notion Mapping table: REST controllers, responses, adapter controllers, aggregates, entities, VOs, ErrorCodes, and SecurityConfig. Everything else is dropped, e.g. domains/post/**, domains/notification/**, and domains/account/social/**.

    No classes remain. The dropped classes are reported with reasons, and no file is written.
  3. 3

    Write the detected-change file

    Write one file per run, with one section per remaining class. It holds pure codebase facts: change kind, layer, facts, and a code excerpt. Notion vocabulary is not allowed. RUN_ID = YYYYMMDD_HHmmss at run start. Files from earlier runs are kept.

    Write.claude/skills/reflect-api-change-into-notion/detected-change/detected_<RUN_ID>.mdWhat changed in the code this run.
  4. 4

    Write reflected-change files, one per Notion page

    For each affected Notion page, derive the exact Notion content to add or replace, using only the detected-change file with the same RUN_ID. Every fact cites its source class in ## Provenance.

    How ## 인증 is derived

    2. In PUBLIC_ENDPOINTS, with no optional read → omit ## 인증
    3. Otherwise (anyRequest().authenticated()) → > **필수(Required)**
    4. Also under /api/admin/** → note the extra ADMIN authority
  5. 5

    Coverage Check

    For each class section in the detected-change file, check that at least one reflected-change file cites that class by fully qualified name in its ## Provenance.

    A class with zero citations had no visible effect on Notion. It is removed from the detected-change file and from its Target Classes line.
    The detected-change file is now empty. It is deleted via the scoped rm, and nothing is applied to Notion.
  6. 6

    Apply to Notion

    For each affected page, take its latest reflected-change file by RUN_ID. Search the named database for the page, fetch its current content, then insert or replace only what ## Notion Content specifies. Nothing else on the page is changed.

    Read.claude/skills/reflect-api-change-into-notion/reflected-change/<RUN_ID>__<db-slug>__<page-slug>.mdThe edit to apply, plus any exception in its Note: field.
    Read.claude/skills/reflect-api-change-into-notion/document-format.mdSkeleton order and Reconciliation Rules for where the content goes.
    Notion MCPAPI 명세 › <Notion DB> › <page>The live API-spec page: found by search, fetched first, then edited.

Guardrails

  • Runs only when invoked by .claude/skills/postprocess-main-code-change/SKILL.md, never on its own initiative.
  • Writes only under its own detected-change/ and reflected-change/ directories, plus Notion pages. Its SKILL.md and document-format.md are read-only.
  • Every fact written to Notion must trace back through ## Provenance to the actual source code. No fact is ever invented.
