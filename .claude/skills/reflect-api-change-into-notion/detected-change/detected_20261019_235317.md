## kr.modusplant.domains.comment.adapter.controller.CommentController

- Change Kind: Modified
- Layer: Controller
- Domain/Package: domains.comment
- Facts:
  - `register` no longer checks that the parent path of a nested `path` exists; the private `validateIfParentCommentExists` (which threw `InvalidValueException(CommentErrorCode.NOT_EXIST_PARENT_COMMENT)`) is removed.
  - `register` converts a non-null `replyToPath` via `CommentPath.create(...)` (throwing `EMPTY_COMMENT_PATH` for a blank value, `INVALID_COMMENT_PATH_FORMAT`, `INVALID_COMMENT_PATH_INDEX`, or `INVALID_COMMENT_PATH_DEPTH` for a depth of 3 or more), then calls `validateIfReplyToCommentPathIsValid`.
  - `validateIfReplyToCommentPathIsValid` throws `InvalidValueException(CommentErrorCode.INVALID_REPLY_TO_COMMENT_PATH, "replyToPath")` unless both `replyToPath` and `path` have exactly two segments and share the same first segment; it then calls `CommentValidationHelper.validateIfCommentExists(postId, replyToPath)`, which throws `NotFoundEntityException(EntityErrorCode.NOT_FOUND_COMMENT)` (404, `not_found_comment`, "댓글이 존재하지 않습니다") when the reply target does not exist.
  - A null `replyToPath` skips both checks; the saved `Comment` carries the `replyToPath`.
  - Pre-existing (unchanged, not a code change): `register` converts `request.path()` through the same `CommentPath.create(...)`, so `INVALID_COMMENT_PATH_FORMAT`, `INVALID_COMMENT_PATH_INDEX`, and `INVALID_COMMENT_PATH_DEPTH` are reachable through `path` as well.
