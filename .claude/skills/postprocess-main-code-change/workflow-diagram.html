postprocess-main-code-change

Runs the required post-processing after code changes under src/main/: tests first, then docs, then Notion API specs, then Confluence table definitions, strictly in that order.

Skill file: .claude/skills/postprocess-main-code-change/SKILL.md. That file is the source of truth; this page is a human-oriented view of it. Steps 1–3 embed that skill's own workflow-diagram.html; step 4 is summarized inline.

  • This skill does no work itself. It only invokes the four skills through the Skill tool, in the conversation it runs in, never as a forked or background subagent. Each step's findings carry forward into the next.
  • Each step starts only after the previous one finishes.
  • If a step terminates because its target set is empty (including after its own scope filter), it is skipped and the chain continues with the next step.
  • If a step terminates early for any other reason, the chain stops there.
  • The report names every skipped or stopped step and the reason, so the user can re-run it manually.
